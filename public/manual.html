01

기술 스택 한눈에 보기

Frontend

Next.js 16 · React 19

App Router 기반. Tailwind CSS 4로 스타일링. 모바일/데스크탑 반응형.

PostgreSQL + Row Level Security. 이메일 OTP 인증. Storage 버킷으로 대용량 원문 분리 저장.

AI Pipeline

Gemini → Groq → Anthropic

주요 라이브러리

react-force-graph · pdf-parse · mammoth

관계도 시각화, PDF/DOCX 파싱, 스프레드시트 처리.

02

사전 준비

로컬 환경에서 DocFlow를 실행하려면 아래 도구가 먼저 설치되어 있어야 합니다.

1

Node.js 20 이상

터미널에서 node -v를 실행해서 v20.x.x 이상인지 확인하세요. 없으면 nodejs.org에서 LTS 버전을 설치합니다.

2

npm 또는 yarn

Node.js 설치 시 npm이 함께 포함됩니다. npm -v로 확인하세요.

3

Supabase 프로젝트 (무료 계정 가능)

supabase.com에서 무료 계정을 만들고 새 프로젝트를 하나 생성해 두세요. URL과 API 키가 필요합니다.

4

AI API 키 (최소 1개)

Gemini API 키만 있어도 동작합니다. Google AI Studio(aistudio.google.com)에서 무료로 발급할 수 있습니다. Groq·Anthropic 키는 없으면 해당 fallback이 건너뜁니다.

03

코드 받고 의존성 설치

프로젝트 폴더 열기

이미 공유받은 ZIP 파일을 풀거나 git clone한 경우, 터미널에서 프로젝트 폴더로 이동합니다.

Terminal cd /path/to/docflow npm install # 의존성 설치 (node_modules 생성)
⚠

node_modules가 이미 있는 경우

공유받은 폴더에 node_modules가 포함되어 있으면 npm install을 건너뛰어도 되지만, OS가 다르거나 Node.js 버전이 다를 경우 충돌할 수 있으니 한 번 실행하는 것을 권장합니다.

04

환경 변수 설정

프로젝트 루트에 .env.local 파일을 직접 만들어야 합니다. 이 파일은 git에 포함되지 않으므로 팀원 각자가 만들어야 합니다.

.env.local (프로젝트 루트에 생성) # ── Supabase ──────────────────────────────────────── NEXT_PUBLIC_SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9... SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9... # ── AI API Keys ────────────────────────────────────── GEMINI_API_KEY=AIzaSy... GROQ_API_KEY=gsk_... # 선택 사항 ANTHROPIC_API_KEY=sk-ant-... # 선택 사항
변수명 어디서 찾나요
NEXT_PUBLIC_SUPABASE_URL 필수 Supabase 대시보드 → Project Settings → API → Project URL
NEXT_PUBLIC_SUPABASE_ANON_KEY 필수 Project Settings → API → anon / public 키
SUPABASE_SERVICE_ROLE_KEY 필수 Project Settings → API → service_role 키 (비공개 — 서버에서만 사용)
GEMINI_API_KEY 필수 Google AI Studio → aistudio.google.com → Get API key
GROQ_API_KEY console.groq.com → API Keys (선택 — 없으면 해당 fallback 건너뜀)
ANTHROPIC_API_KEY console.anthropic.com → API Keys (선택 — 없으면 해당 fallback 건너뜀)
🔒

service_role 키 주의

SUPABASE_SERVICE_ROLE_KEY는 RLS를 우회하는 관리자 키입니다. NEXT_PUBLIC_ 접두어를 붙이면 절대 안 됩니다. 서버 API 파일에서만 사용됩니다.

⚡

셸에 ANTHROPIC_API_KEY가 이미 있다면

시스템 환경 변수가 .env.local보다 우선됩니다. 빈 값으로 설정된 경우 API 오류가 납니다. 서버 실행 전 unset ANTHROPIC_API_KEY를 먼저 실행하세요.

05

Supabase 프로젝트 설정

Supabase는 DB, 인증, 파일 스토리지를 모두 담당합니다. 아래 순서대로 설정합니다.

새 프로젝트 만들기

1

supabase.com 접속 → New Project

Organization을 선택하고 프로젝트 이름(예: docflow-team), 데이터베이스 비밀번호, 리전(ap-northeast-1 도쿄 권장)을 입력합니다.

2

프로젝트 생성 완료 대기 (~1분)

대시보드 상단에 "Setting up your project" 스피너가 사라지면 완료입니다.

3

API 키 복사

Project Settings → API에서 Project URL, anon 키, service_role 키를 복사해 .env.local에 붙여넣습니다.

06

DB 스키마 적용

Supabase 프로젝트를 만든 직후에는 테이블이 없습니다. SQL Editor에서 스키마를 직접 실행해야 합니다.

1

SQL Editor 열기

Supabase 대시보드 왼쪽 메뉴에서 SQL Editor를 클릭합니다.

2

schema.sql 내용 붙여넣기

프로젝트 폴더의 supabase/schema.sql 파일 전체 내용을 복사해서 SQL Editor에 붙여넣습니다.

3

Run 버튼 클릭 (또는 Cmd+Enter)

오류 없이 실행되면 성공입니다. 아래 테이블이 생성됩니다: workspaces, workspace_members, services, documents, doc_relations, schedules.

4

마이그레이션도 실행

supabase/migrations/20260424143000_workspace_membership.sql도 마찬가지로 SQL Editor에 붙여넣고 실행합니다.

5

Table Editor에서 확인

왼쪽 메뉴 Table Editor에서 6개 테이블이 보이면 완료입니다.

✓

기본 공유 워크스페이스 자동 생성

schema.sql에는 DocFlow Shared Workspace (ID: 00000000-0000-4000-8000-000000000001)를 INSERT하는 구문이 포함되어 있습니다. 새로 로그인한 팀원은 이 공유 워크스페이스에 자동으로 추가됩니다.

07

Auth 이메일 OTP 설정

DocFlow는 비밀번호 없이 이메일로 일회용 코드(OTP)를 받아 로그인합니다. Supabase에서 활성화해야 합니다.

1

Authentication → Providers 이동

Supabase 대시보드 왼쪽 메뉴 Authentication → Providers를 클릭합니다.

2

Email 섹션 → "Enable Email OTP" 활성화

Email 항목을 열면 Enable Email OTP 토글이 있습니다. ON으로 바꾸고 Save합니다.

3

Redirect URL 등록

Authentication → URL Configuration에서 Site URL을 http://localhost:3000으로 설정합니다. 실서버에서는 실제 도메인을 추가합니다.

📧

무료 플랜 이메일 발송 제한

Supabase 무료 플랜은 시간당 3건의 이메일 발송 제한이 있습니다. 테스트 시 너무 자주 요청하면 일시적으로 막힐 수 있습니다.

08

Storage 버킷 생성

대용량 문서 원문(OCR, 이미지 미리보기 등)은 Supabase Storage에 분리 저장됩니다. 버킷을 미리 만들어야 합니다.

1

Storage → New Bucket

Supabase 대시보드 왼쪽 Storage 메뉴 → New bucket 버튼을 클릭합니다.

2

버킷 이름 입력

이름을 정확히 docflow-document-details로 입력합니다. Public 여부는 Private(기본값)으로 둡니다.

3

Create 클릭

버킷 목록에 docflow-document-details가 나타나면 완료입니다.

✦

오른쪽 채팅 패널에 파일 드래그 또는 URL 붙여넣기

AI가 자동으로 분석 후 카드 생성

모드설명
map서비스 노드 중심의 계층 맵. 전체 구조 파악에 적합

권한 owner admin member viewer
문서 조회 ✓ ✓ ✓ ✓
문서 등록/수정/삭제 ✓ ✓ ✓ —

ℹ

마지막 owner 보호

워크스페이스에 owner가 1명만 남아 있을 경우 해당 멤버의 역할을 변경하거나 제거할 수 없습니다. 다른 멤버에게 owner 권한을 먼저 부여해야 합니다.

로그인이 안 될 때

!

Supabase 프로젝트 pause 여부 확인

Supabase 대시보드에서 프로젝트 상태를 확인합니다. Paused 상태면 Restore 버튼을 클릭합니다.

!

.env.local 변수 오탈자 확인

NEXT_PUBLIC_SUPABASE_URL이 https://로 시작하는지, 따옴표나 공백이 없는지 확인합니다.

AI 분석이 응답 없이 멈출 때

!

GEMINI_API_KEY 유효성 확인

Google AI Studio에서 키를 재발급하거나, 키에 공백이 포함되지 않았는지 확인합니다.

!

셸 환경 변수 충돌 확인

터미널에서 echo $ANTHROPIC_API_KEY를 실행해서 값이 출력되면 충돌 가능성이 있습니다. unset ANTHROPIC_API_KEY 후 서버를 재시작합니다.

워크스페이스 생성이 실패할 때

!

DB 스키마 미적용 여부 확인

Supabase Table Editor에서 workspaces 테이블이 존재하는지 확인합니다. 없으면 06단계의 schema.sql 실행부터 다시 합니다.

!

service_role 키 확인

워크스페이스 생성은 SUPABASE_SERVICE_ROLE_KEY를 사용합니다. anon 키를 잘못 넣었는지 확인합니다.

MVP 테스트 체크리스트

팀원 전원이 아래 항목을 직접 수행해보면서 기능을 검증합니다.

  • 이메일 OTP로 로그인 성공
  • 기존 워크스페이스 목록이 보이는지 확인
  • 새 워크스페이스 생성 후 전환 확인
  • 파일(PDF 또는 DOCX)을 채팅에 드래그해서 카드 자동 생성 확인
  • URL을 채팅에 붙여넣어서 웹 문서 카드 생성 확인
  • 자연어로 카드 상태 변경 ("○○ 문서 상태 완료로 변경해줘")
  • 카드 클릭 → 상세 모달에서 정리본 탭 내용 확인
  • 타임라인 탭에서 일정 추가 및 수정 확인
  • 관계도 탭에서 서비스 노드와 문서 연결 확인
  • 워크스페이스에 다른 팀원 초대 (이메일 기준)
  • 초대된 팀원이 동일한 문서 목록을 볼 수 있는지 확인
  • 다른 워크스페이스로 전환 시 문서가 분리되는지 확인
